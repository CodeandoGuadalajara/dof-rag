# DOF RAG PoC

Hybrid RAG proof-of-concept for the Mexican **Diario Oficial de la Federación** using:

- **Embeddings:** `pplx-embed-context-v1-0.6b` (Perplexity) running locally via ONNX Runtime — 1024 dims, contextual late chunking
- **Vector search:** `sqlite-vec` (Alex Garcia) — `vec0` virtual tables + KNN
- **Full-text search:** SQLite FTS5
- **Hybrid ranking:** Reciprocal Rank Fusion (RRF)

## Quick start

### 1. First run (downloads ~1.2 GB ONNX model)

```bash
# Model is cached automatically on first use (~1.2 GB)
# Default cache: ./rag_poc/.model_cache/

# Index a sample directory
python -m rag_poc.cli index ./dof_md/2020/01/15012020/MAT

# Index with more parallelism (local inference — safe to increase)
python -m rag_poc.cli index ./dof_md/2020/01/15012020/MAT --batch-size 16
```

### 2. Search

```bash
python -m rag_poc.cli search "subsidio federal articulo 47 vivienda"
python -m rag_poc.cli search "resolucion miscelanea fiscal 2024"
```

### 3. Stats

```bash
python -m rag_poc.cli stats
```

## Architecture

```
markdown file
    │
    ▼
┌─────────────────┐
│  chunker.py     │  ← pattern classifier (5 doc types) + custom splitters
└─────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  embedder.py                                                │
│  ├── tokenizer (HF AutoTokenizer, trust_remote_code)       │
│  ├── ONNX Runtime session (local CPU, ~1.2 GB model)       │
│  └── late chunking: SEP-split concatenated sequences       │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────┐
│  SQLite                                 │
│  ├── documents       (metadata)         │
│  ├── chunks          (text + headers)   │
│  ├── chunks_fts      (FTS5 virtual)     │
│  └── chunks_vec      (sqlite-vec KNN)   │
└─────────────────────────────────────────┘
    │
    ▼
┌─────────────────┐
│  search.py      │  ← RRF(vector_knn, fts_bm25) → final top-k
└─────────────────┘
```

## Chunking strategy

| Pattern | Trigger | Strategy |
|---|---|---|
| `small` | < 10 KB | Single chunk |
| `h2_compound` | ≥2 H2 headings | Each H2 = atomic chunk; H3 sub-split if needed |
| `bold_headers` | ≥2 bold lines | Bold lines as metadata header; split by paragraphs |
| `plain_text` | No structure | Paragraph split with overlap |
| `giant_table` | >40% lines are tables | Table-aware chunking with repeated column headers |

`IMAGE_DESCRIPTION` HTML comments generated by `enrich_markdown_images.py` are inlined as plain text so images are searchable.

## Why local ONNX instead of API?

- **Cost:** Zero per-request cost for large-scale indexing
- **Speed:** No network latency; batch inference on CPU is fast
- **Contextual correctness:** The model sees all chunks of a document together via SEP-token concatenation — impossible to replicate with per-chunk API calls
- **Privacy:** No document text leaves the server

## Late chunking explained

Standard embedding APIs process each chunk independently. `pplx-embed-context-v1` is a **contextual** model: chunks from the same document must be concatenated with `SEP` tokens so the model sees them in shared context.

```python
# Input to tokenizer
doc_string = chunk1 + SEP + chunk2 + chunk3

# After ONNX inference, we split the token-level output back into
# per-chunk embeddings by locating SEP positions.
```

This is handled automatically by `embedder.py`.

## Hybrid search formula

Reciprocal Rank Fusion with `k=60`:

```
RRF_score = Σ 1 / (rank_i + 60)
```

Where `rank_i` is the rank from each subsystem (vector KNN and FTS5 BM25).

## Notes / future work

- sqlite-vec uses brute-force KNN. For >100k chunks consider `sqlite-vec` metadata partitions or switch to approximate indexes.
- The ONNX model can be quantized (`model_quantized.onnx`) for ~2× faster inference at slightly lower accuracy.
- For production, add an LLM reranker (e.g. Cohere Rerank or cross-encoder) after the RRF stage.
