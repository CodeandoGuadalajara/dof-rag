6. 8. Produce a final comparison with speed/correctness/memory trade-offs, identify the recommended stack and verified alternative, leave a documented healthy deployment, and audit every goal requirement against fresh evidence before completion.

## Safety and service restoration

Never overlap large GPU stacks. Check active requests, unit states, health, ports and memory before switches. Cancel launch/eval units before rollback and separately stop Docker download containers if needed: killing their clients does not necessarily stop containers. Preserve checkpoint files (AutoRound local/HF-cache files are hard-linked; never mutate in place). Keep unauthenticated APIs on trusted networks. Do not alter unrelated Pi-web or embedding services; pause only the pilot services required by the runbook, with state-aware systemd restoration. Avoid competing endpoint requests during evaluation.
